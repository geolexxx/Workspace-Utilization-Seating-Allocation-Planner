# Workspace Utilization & Seating Allocation Planner

A portfolio piece targeting a **Real Estate Planning & BP Analyst** role (corporate workspace / facilities planning). The tool demonstrates three core competencies: space utilization analysis, planning dashboards, and translating headcount plans into seating allocations.

> **All data is synthetic.** The 12-week badge-swipe occupancy dataset is generated by a seeded simulation (`scripts/generate-data.ts`). No real building, team, or employee data is used anywhere.

---

## Quick start

```bash
npm i && npm run dev
```

Open `http://localhost:5173`.

## What it does

Simulates a fictional **Americas office portfolio**: 434 desks across 4 floors / 8 neighborhoods / 12 teams, each with a headcount and a hybrid working model (average in-office days/week).

The headline insight the tool surfaces:

> Portfolio-wide utilization is ~50%, yet Central Hub (L3-A) peaks at **110% — over capacity** — while three neighborhoods sit below 40%. The problem is _distribution_, not a desk shortage.

The interactive **Allocation Engine** lets you drag a utilization-ceiling slider and see which teams move where, which zones are relieved, and how many desks become recoverable — without adding a single seat.

## Modeling assumptions

### 1. Daily attendance simulation

For each team and each of the 12 × 5 = 60 simulated working days:

```
daily_presence ~ Binomial(headcount, in_office_rate × dow_weight[day])
in_office_rate  = in_office_days / 5
dow_weight      = [Mon 0.85, Tue 1.15, Wed 1.23, Thu 1.07, Fri 0.70]
```

The day-of-week multipliers average to 1.0, so the weekly mean matches each team's stated `in_office_days`. They reproduce the empirically common midweek peak / Friday collapse profile.

### 2. Effective demand = 95th-percentile peak seats

```
peak_demand  = percentile(daily_presence, 95)   -- per team
peak_util    = percentile(zone_daily_occ, 95) / desks  -- per zone
```

Planning to the **mean** would leave people deskless on peak days. The 95th percentile captures realistic worst-case concurrent presence. This is the key modeling decision to explain in interviews.

### 3. Allocation engine

A transparent greedy heuristic — no black-box solver:

1. Identify zones where `peak_demand > desks × ceiling`.
2. Sort movable teams smallest-first (least disruption principle).
3. For each team, prefer a **single same-floor destination** (scored = `spare_capacity − floor_penalty`). Floor penalties: same floor = 0, adjacent = 15, two+ away = 30 seat-equivalents.
4. Only split a team across zones when no single zone can absorb it.

Every number is traceable to a desk count and a ceiling. No parameter tuning required.

## Regenerating the dataset

```bash
npm run gen
```

Re-runs the simulation with the same seed (`42`) and overwrites `src/data/workspace.json`. Change `SEED` in `scripts/generate-data.ts` to produce a different-but-reproducible dataset.

## Running tests

```bash
npm test
```

Tests assert: no zone exceeds the ceiling when feasible; the hotspot is relieved; total peak seats are conserved; the cohesion constraint routes teams to same-floor destinations when capacity exists.
